## 회고

### 예상과 달랐던 점
1. **mounjaro.md 품질 부족 발견** — 당연히 품질 정합된 md로 가정하고 fixture 삼았으나, PMID/DOI 없고 "시작 용량" 섹션은 출처 자체 없음. 초기 설계서 v1에서 내가 PMID를 추정해 넣은 건 명백한 fake data. 미르의 "자료로서 가치 떨어져" 지적 없었으면 그대로 main 반영됐을 것.
2. **sources[] 배열이 사문화 상태** — runtime consumer code 추적 전에는 "sources[]에 정밀 메타 저장하면 UI에 반영된다"고 암묵 가정했으나, 실제로는 `content` 문자열 외 어떤 배열도 UI 경로에 흐르지 않음. Phase 3B의 실제 "출처 UI 전달"은 content text 수준뿐.
3. **Boss 재검토의 실효** — 2026-04-19 확정한 "자동 swap + confidence" 방안이 Phase 3B 착수 단계에서 미르 의문 한 문장으로 폐기됨. 이미 확정된 설계도 Boss 4관점 재검토로 자유롭게 뒤집을 수 있음이 확인됨 — 좋은 정신적 유연성.

1. **Fixture 선정 시 md 원본 품질 검증 선행**: Phase 4 마이그레이션에서는 `knowledge/by-*/*.md` 중 출처 밀도 낮은 파일(mounjaro 포함) → Liby + Researcher 호출로 보강 선행 후 bundle 컴파일.
