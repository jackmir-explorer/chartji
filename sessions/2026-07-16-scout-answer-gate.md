- 6월 초부터 체크 끊김, 6월 중순~7월: Scout PR 머지 자체를 안 함 → **open PR 39개(#73~#111)** 누적. 트리거는 매일 성실히 돌며 아무도 안 읽는 보고서 생산.
- 근본 원인: 파이프라인에 미르의 사고가 개입하는 지점이 체크박스 탭 1회뿐. 비용이 0이라 전량 체크 or 전량 방치로 양극화.

### 채택 방향 — 아이디어 #1 (답변 게이트)만 우선
미르 지시: "PR은 전부 삭제하고 처음부터 하자. 우선 1번만."

`[o]` 체크박스(무비용 탭)를 **💬 한 줄 반응(한 문장 작성)**으로 교체. 탭 1회는 생각 없이 가능하지만 한 문장은 생각 없이 불가능 → 5월의 "전량 체크" 실패를 구조적으로 차단. 파인만의 "자기 언어로 끌어안기"를 ingest의 통화(currency)로 만듦.

> 5→1 축소, 질문형 제목, 복습 슬롯(아이디어 #2·#3)은 이번 범위 제외 — 후속 세션.

## 건드린 파일 상세

### 밀린 PR 정리
- Scout PR #73~#111 (39개) 전량 close (GitHub MCP `update_pull_request state=closed`).
  - `git push origin --delete`는 이 환경에서 HTTP 403 → 원격 브랜치 삭제 불가. 열린 PR 0개이므로 알림·목록 노이즈는 제거됨. `claude/scout-2026-06-07`~`2026-07-16` 브랜치는 원격에 잔존(무해).

### `routines/scout.md`
- Step 4 결과 파일 템플릿: `- **Deep Extract:** [ ] ← 원하면 [o]로` → `- **💬 반응:** \`___\``. 템플릿 상단에 답변 게이트 안내 블록 추가.
- 논문 상태 마커 표: `[ ]/[o]/[⏳]/[✓]/[x]` 5종 → 반응 필드 3상태(`___` 미확인 / {한 문장} 신호 / {한 문장}+`✅ 반영됨` 완료)로 개편. 스킵은 반응 미작성으로 자동 처리(별도 마커 폐지).
- 실행 주기 설명(Step 상단), Step 2-B 중복차단 예외, Step 6 footer 마지막 줄, Step 7-3 흐름 — `[o]/[x]/[ ]` 표현을 반응 게이트 표현으로 통일.

### `routines/deep-extract.md`
- 목적: `[o]` 체크 → 💬 반응 작성 논문. 반응 한 문장을 study-note에 "미르의 첫 반응"으로 저장(knowledge/*.md에는 미주입 — 격리 원칙).
- Step 1 대상 수집: 판정 규칙 명문화 — 반응 줄에서 백틱·공백 제거 후 비어있지 않고 `___`도 아니며 `✅ 반영됨` 태그 없는 논문만 처리.
- Step 2-B study-note 템플릿: `## 미르의 첫 반응` 섹션 추가(출처 Scout 아래).
- Step 3 마커 업데이트: `[o]`→`[✓]` 치환 → 반응 줄 끝에 `✅ 반영됨 YYYY-MM-DD` 태그 부착(반응 텍스트 보존). 10건 초과 backlog 유지 표현도 태그 기준으로 수정.
- 과거 누락 복구 표현 수정.
