## Builder 결과

### 변경 #1 — `src/app.js` handleCuration v2 분기
v2 분기에 2개 inject 추가, v1 경로는 미수정.
```js
if(e.primarySources&&e.primarySources.length){
  knowledgeCtx+="["+c+".primarySources]\n"+e.primarySources.join("\n")+"\n\n";
}
keys.forEach(function(k){
  var s=e.sections[k]; if(!(s&&s.content)) return;
  knowledgeCtx+="["+c+"."+k+"]\n"+s.content;
  if(s.sources&&s.sources.length) knowledgeCtx+="\n[sources]\n"+s.sources.join("\n");
  knowledgeCtx+="\n\n";
});
```

### 변경 #2 — `src/prompts.js`
A. 역할 분업 문단 재작성 (v1 시대 "treatment·differential은 Liby 힌트 담당, 너는 exam·draftAppend만" → v2 dispatch 현실과 일치하도록 "입력 블록 = Guide tab 할당 섹션만" 원칙으로 단순화).

B. 출처 규칙에 ⑧ 추가:
```
⑧ 지식 자료 블록 본문 뒤에 [sources] 하위 블록, 또는 별도 [키.primarySources] 블록이 붙어 있으면:
    · bullet 근거로 가장 부합하는 항목 1개를 그대로 [출처: <항목 원문>] 에 사용
    · 예: [sources] "Ryan D. ... PMID:36225262, DOI:10.1002/clt2.12195"
           → [출처: Ryan D. ... PMID:36225262]
    · 해당 섹션 [sources]가 비어 있고 [키.primarySources]만 있으면 primarySources 항목 중 하나 선택
    · 둘 다 없으면 ②~⑤ 규칙으로 fallback
```

## 회고

### 예상과 달랐던 점
1. **guide hook과 sections 교집합이 예상보다 작음** — urticaria의 guide hook은 7개 키(classification/exam/monitoring/contraindication/pregnancy/referral/differential), 실제 sections에 있는 건 4개. 나머지 3개는 엔트리에 해당 섹션이 없어 자동 skip. 이는 정상 동작이지만 "guide가 7개 다 흐른다"는 암묵 가정이 틀렸음을 확인.
2. **sources 배열 채움 밀도가 더 낮음** — urticaria 엔트리 7개 섹션 중 sources 있는 건 3개(protocol/pregnancy/ocs-short-term-limit). 그 중 guide hook과 교집합은 pregnancy 1개뿐. 나머지 2개(protocol·ocs-short-term-limit)는 Guide tab에 안 나오므로 3C 효과 없음. Phase 4에서 ocs-short-term-limit 같은 "hook 외 섹션"을 어떻게 처리할지가 결정 포인트로 떠오름.
3. **역할 분업 문구가 v1 시대 가정에 지나치게 종속** — "Liby 힌트가 treatment·differential 담당"은 v1 shape 이야기. v2에서는 hint hook = `["protocol"]`이 기본이고 differential은 guide에 들어감. 이 불일치를 3C 설계 중에 발견해 문구 단순화(입력 범위 = Guide 할당 섹션)로 재작성.
