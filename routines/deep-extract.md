# Routine: Deep Extract (md 파일 자동 반영)

## 실행 방식
**매일 정오 12:00 자동 실행**
Scout가 6시에 생성한 보고서를 미르가 오전 중 핸드폰으로 확인·체크할 수 있도록
6시간 간격을 두고 실행한다.

**데스크탑에서 수동 실행도 가능:** "deep extract 실행해줘"

## 목적
Scout ⭐ 항목 중 미르가 `[o]` 체크한 논문을
`skills/paper-extract/SKILL.md` 로 정식 knowledge 형식(`.md`)으로 추출하고
**study-notes 풀 임베드 PR을 생성**해 모바일에서 그대로 공부하면서 머지하도록 한다.

> ⚠ **이 routine은 `knowledge/*.md` 파일 반영까지만 수행**한다.
> 앱 Guide/Hint/Draft에 실제 노출되려면 **Liby 별도 호출**로 `src/knowledge-bundle.js` 컴파일 필요 (수동 — 판단이 많아 자동화 위험).
> 완료 보고·PR body에도 이 경고를 반드시 포함한다.

> 📚 **공부 워크플로우 (2026-05-26 재편)**: study-notes 개별 파일을 열어보는 번거로움 해소.
> Deep Extract PR body에 study-notes 전체 본문이 임베드됨 → 미르는 모바일 GitHub 앱에서
> **PR description을 읽으면서 공부** → 다 읽으면 머지. 별도 파일 열기 불필요.

## 실행 절차

### Step 1 — 대상 수집

`inbox/scout/` **전체 파일**에서 `[o]` 체크된 항목 수집 (미르가 Scout 파일에서 `[ ]` → `[o]` 로 변경한 항목).

- **오늘자만 처리하지 않는다.** 과거 날짜의 `[o]` 항목도 누락 복구 대상.
- 각 항목의 출처 Scout 파일 날짜를 추적 (요약에 "과거 누락 복구" 섹션으로 표기).
- 대상이 없으면 조용히 종료 (로그 없음 — 정상 동작).

### Step 2 — 논문별 Deep Extract

각 대상 논문에 대해 `skills/paper-extract/SKILL.md` 실행:
1. PubMed/저널 사이트에서 초록 + 결론 수집
2. 임상 핵심 추출
3. knowledge/ 형식 draft 작성
4. 저장 위치 결정 (기존 파일 추가 or 신규 생성)

### Step 2-B — 공부 보고서 생성 (2026-04-24 신설, A층 순수학습용)

Step 2와 **동시에** 각 논문에 대한 공부 보고서를 `inbox/study-notes/` 에 생성한다.

**저장 경로**: `inbox/study-notes/YYYY-MM-DD-[논문제목-slug].md`
- `YYYY-MM-DD` = 실행 당일 KST
- `[논문제목-slug]` = 논문 제목을 kebab-case 영문 슬러그 (또는 짧은 한글). 예: `glp1-adolescent-obesity`, `influenza-rx-model`

**양식 원칙** (2026-05-05 개정):
- **연구 본래 narrative 보존이 우선** — 초록 요약·배경·한계는 논문이 강조한 message 그대로 살림. 미리 정한 frame에 짜맞추기 금지.
- **"일차의료 적용 포인트"만 자연스럽게 깊게** — 논문이 제공하는 영역에서만 sub-bullet 작성. 강제 N/A 표기 X, 강제 frame X.
- **할루시네이션 방어**: 한국 brand·보험·구체 분기 임계값은 논문에 명시되지 않으면 `[출처 미확인 — researcher 검증 권장]` 또는 `[가이드라인 default 인용: {출처}]` 명시. 추정 금지.

**양식**:
```markdown
# {논문 제목}

- **PMID**: {번호}
- **저널 / 연도**: {저널명} {연도}
- **저자**: {제1저자 et al.}
- **출처 Scout**: inbox/scout/YYYY-MM-DD.md

## 초록 요약
{초록 재구성 — 원문 재현 금지, 2~3문단. 연구의 main message·강조점 보존}

## 일차의료 적용 포인트

논문이 제공하는 영역에서만 sub-bullet 작성. 모든 sub-bullet 강제 X — 자연스러운 영역만.

### 약물·처방 디테일 (해당 시 — 논문이 처방 가이드 포함할 때)

{이 논문의 발견이 외래 결정에 어떻게 반영되는지 — 단계·임계값·시점}

- {한국 brand·보험·가용성 [출처 미확인] 영역 명시}
- {한국 임상 외삽 위험}

## 관련 knowledge/ 엔트리
- {Deep Extract가 반영한 knowledge/ md 파일 경로}
- 관련: {다른 entry 양방향 link 가능 시}
```

**양식 적용 예시** (2026-05-05 추가):
- **임상 가이드형** (In the Clinic / NEJM Clinical Practice / AFP): 진단·약물·결정 분기·환자 교육 모두 자연스럽게 채워짐
- **RCT 효능** (NEJM 등): 약물 디테일은 가이드라인 default 인용, 결정 분기는 "이 환자 type에 적용", 환자 교육은 효능 결과 기반
- **메타·체계적 고찰**: 약물 디테일은 가이드라인 default 인용, 효능 합성을 임상 결정에 어떻게 반영할지
- **관찰 연구** (처방 패턴 등): "임상 시사점" 위주, 표준 약물 디테일은 별 entry 인용
- **시스템·정책 연구**: 약물 디테일 sub-bullet 자체를 안 만듬 (강제 N/A 표기 X). "어떤 환자에 적용 / 미적용 / 한국 적용 시 핵심"이 자연스러움

> 핵심: **논문 type별로 sub-bullet 구성 자연스럽게 다름**. 강제 양식 X — 연구 본래 메시지 보존 + 적용 가능 영역 깊게.

## 주의사항

- CLINICAL 항목은 반드시 출처(PMID) 표기
- 기존 파일 내용 삭제 금지 — 추가만 허용
- 한 번 실행당 최대 논문 **10건** (과부하 방지). 10건 초과 시 우선순위 높은 것부터 처리하고 나머지 `[o]` 유지 (다음 trigger에서 재처리). 기존 5건 상한은 2026-04-23 백로그 누적 사례로 상향 (미르 지시).
- 요약 보고서의 "⚠ 다음 단계" 경고는 양식 그대로 유지 — 미르가 헷갈리지 않도록 매번 같은 문구 사용.
- **md 파일과 bundle은 별도 반영 구조**임을 모든 산출물에 명시. 이 구조 자체는 의도된 설계(자동화 위험 관리) — 혼동만 제거하는 것이 이 routine의 책무.
